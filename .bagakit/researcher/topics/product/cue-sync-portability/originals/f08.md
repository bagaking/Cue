## Why It Matters

Exercises FileManager directory replacement with retained backup, pre/post-publication process stops, and two independent NSFileCoordinator writers.

## Observed Results

- successful same-parent directory replacement: complete `live=new` and
  retained complete `backup=old`;
- child `abort()` inside the coordinated accessor before publication:
  complete `live=old`, complete staged new, and no backup created;
- child `abort()` immediately after replacement: complete `live=new` and
  retained complete `backup=old` after process death;
- two independent child processes used `NSFileCoordinator` write
  `options: []` with the same supplied expected generation, and each read live
  inside its accessor before attempting replacement: exactly one returned
  success, the other observed the changed live generation and returned a typed
  expected-revision conflict, and live was a complete winner package.

The first sandboxed run failed before the accessor with Cocoa error 512 because
the system coordination daemon could not access that sandbox's temporary item.
That environmental failure is not evidence against the API and is why the
recorded probe requires an unsandboxed local run.

## Limitations
- One macOS 26.3.2 APFS host and process termination only; no power cut, kernel crash, alternate filesystem, provider, or dual-Mac transport is tested.
