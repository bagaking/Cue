## Why It Matters

Defines same-volume safe replacement, same-parent fallback staging, backup retention, and displaced-original recovery.

## Retained Contract Excerpts

- Apple describes the method as replacing an item's contents "in a manner
  that ensures no data loss occurs."
- `newItemURL` must be on the same volume. When an OS replacement directory is
  unavailable, Apple recommends a uniquely named item in the original item's
  directory.
- A named backup is created beside the original; replacement fails if backup
  creation fails. `withoutDeletingBackupItem` keeps that backup after success.
- The returned URL may differ from `originalItemURL`, and an error can report a
  displaced original through `NSFileOriginalItemLocationKey`.

## Limitations
- The public API contract does not document power-loss durability, directory fsync, or the internal syscall sequence.
