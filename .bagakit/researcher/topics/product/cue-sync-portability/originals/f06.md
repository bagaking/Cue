## Why It Matters

Defines coordinated access for files/directories, file-package interactions, accessor URLs, and writing-option behavior.

## Retained Contract Excerpts

- The synchronous read and write methods accept a file or directory and
  require callers to use the URL passed into the accessor.
- Coordination waits on participating operations for the exact directory.
  File-package operations additionally notify relevant package presenters.
- A read with `options: []` asks relevant presenters to save changes before
  the accessor. A write with `options: []` represents a content mutation of
  the same document.
- `forReplacing` changes presenter/move semantics and is recommended when
  creating or moving an item should replace whatever is at a location; it is
  not itself a compare-and-swap or a safe-save implementation.

## Limitations
- Coordination serializes participating coordinators and presenters; it does not create semantic CAS or prove non-participants are safe.
